Please implement one minimal, upstream-shaped optimization in this
`wit-bindgen` checkout.

## Goal

Optimize only the generated MoonBit async outgoing `stream<u8>` write path:
replace its per-byte canonical lowering loop with one bulk copy.

## Read first

Read these files completely before editing:

1. `docs/moonbit-p3-knowledge/README.md`
2. `docs/moonbit-p3-knowledge/topics/wit-bindgen-byte-fast-path.md`
3. `docs/moonbit-p3-knowledge/topics/component-model-ownership.md`
4. `docs/moonbit-p3-knowledge/evidence-summary.md`
5. `crates/moonbit/docs/async-design.md`

Confirm that the branch contains upstream commits `ce2815c` (#1665) and
`7c48901` (#1664).

## Strict scope

- Handle only `u8` whose MoonBit and canonical memory representation is
  byte-for-byte identical.
- Preserve the current `Sink::write` owned `FixedArray` snapshot.
- Preserve the current canonical allocation.
- Preserve the current approximately 4 KiB primitive window.
- Preserve the existing `Stream`, `Sink`, `Mutex`, callback, terminal,
  cancellation, partial-progress, commit, reject, and cleanup lifecycle.
- Keep all non-byte, nested, and resource-bearing payloads on the existing
  scalar path.
- Do not change the incoming stream path.
- Do not change public APIs.
- Do not move lowering before the writer lock.
- Do not merge the `FixedArray` snapshot with canonical storage in this task.
- Do not introduce `CanonicalOwner`, `RefCell`, static borrow, zero-copy,
  endpoint vtables, or a new shared-runtime abstraction.
- Do not modify the stream window in this task.

The intended source area is the outgoing stream callback generated by
`generate_async_future_or_stream_import` in
`crates/moonbit/src/async_support.rs`. Inspect the existing generator and FFI
helpers before choosing the mechanism.

## Stop condition

If a safe bulk copy requires any of the following, stop and report the exact
missing primitive instead of expanding the design:

- retaining a raw pointer across suspension;
- changing the callback to own a different type;
- moving lowering before lock acquisition;
- changing cancellation or progress settlement;
- adding a general ownership state machine.

A useful result may be a precise, small missing-intrinsic proposal rather than
an unsafe implementation.

## Correctness requirements

- Generate the bulk path only when the element type is exactly canonical
  `u8`, including transparent aliases only if the generator can prove the same
  representation.
- Preserve existing address, length, bounds, and overflow behavior.
- Verify lengths 0, 1, 64, 65, 4096, 4097, and 65536.
- Verify response contents and SHA-256, not only response length.
- Verify that mutating the caller's original view after the send starts cannot
  change the staged bytes.
- Keep closed-writer, cancellation, peer-drop, and partial-progress behavior
  on the existing lifecycle.
- Verify that non-byte and resource-bearing streams still generate the old
  lowering path.

## Implementation style

- Make the smallest readable diff.
- Prefer an existing representation-safe FFI helper if one exists.
- Do not add a helper that is only a disguised one-use code fragment.
- Add a short comment only where it explains the representation invariant or
  why the owner remains live.
- Preserve unrelated worktree changes.

## Validation

At minimum:

1. Add or update generator unit tests showing that `stream<u8>` selects the
   bulk path.
2. Add a negative generator test for a non-byte or resource-bearing stream.
3. Run `cargo test -p wit-bindgen-moonbit`.
4. Run the relevant MoonBit generated/composed runtime tests available in the
   repository.
5. Run exact response-byte/hash verification.
6. If the benchmark harness is available, compare CPU/request and retired
   instructions/request before and after.

Do not require a large saturated-RPS improvement: the operation window remains
unchanged, so this task primarily targets per-request work.

## Final report

Report:

- files changed;
- the representation and lifetime argument that makes the bulk copy safe;
- tests and benchmark results;
- any missing toolchain primitive or unresolved risk;
- confirmation that bounded-window tuning is a separate future task.

Do not push or open a PR unless explicitly asked.
